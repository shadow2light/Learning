## 1. 项目概述

- **业务形态**：陪玩撮合平台。玩家浏览/指定陪玩，按小时单价下单，平台撮合并抽佣。
- **用户规模**：预估约 1000 用户（预计 DAU 100~300，同时在线十几~几十人）。
- **下单模式**：玩家**指定陪玩**下单（非派单/抢单），按**小时**计费。
- **端组成**：
  - 微信小程序前端（`frontend/`）
  - Go 后端（`backend/`，本工程）
  - 管理后台前端（**另一个独立工程**，本工程只交付管理端 API + Swagger 文档）
- **目标运行平台**：Ubuntu Linux（24.04 LTS）。
- **功能边界（一期）**：
  - ✅ 图文/视频**动态广场**
  - ❌ 语音房、直播等实时音视频功能
  - ❌ "附近的陪玩"地理位置功能

### 订单状态机

```
待支付 ──支付成功──▶ 已支付待接单 ──陪玩确认──▶ 服务中 ──完成──▶ 已完成 ──▶ 已评价
  │                    │                                          
  └─超时未支付─▶ 已取消   └──────────退款流程──────────▶ 退款中 ──▶ 已退款
已完成订单进入 N 天结算冻结期 → 冻结期满生成结算单 → 后台审核 → 手动打款回填凭证
```

## 5. 关键业务规则

1. 玩家**指定陪玩**按小时下单，金额 = 小时单价 × 时长。
2. 服务完成后进入 **N 天结算冻结期**（退款窗口过后再打款），N 后台可配。
3. 平台抽佣比例后台可配；陪玩实得 = 订单金额 ×（1 − 抽佣比例）。
4. 陪玩入驻必须**实名认证**，后台审核通过后才可接单。
5. 陪玩收款须实名；未来量大涉及代扣个税（灵活用工）时咨询财务。
6. 用户注销入口为合规必备（小程序审核要求）。
7. 一期结算流程：系统生成结算单 → 后台审核 → 运营线下转账 → 回填凭证（流水号/截图）。

## 6. 支付与结算决策记录

### 6.1 名词解释

- **微信支付分账**：玩家付款后资金冻结在微信侧，服务完成后由接口按比例实时拆分（抽佣进平台、余款直进陪玩零钱）。需单独向微信申请开通、每个陪玩添加为分账接收方并实名。
- **商家转账到零钱**：钱先全额结算到平台商户号，平台再按周期批量打款给陪玩。接口简单、无额外开通门槛。

### 6.2 决策

- [x] 一期**不接分账**，采用"结算单 + 手动转账回填凭证"起步
- [ ] 二期：接入「商家转账到零钱」API 实现自动打款
- [ ] 远期：当财务/合规明确要求"资金不过平台账户"时再评估分账
- [x] 退款一期必做：微信支付 V3 退款接口 + 退款回调 + 幂等 + 状态机

## 9. 合规与风险注意事项

1. **内容安全是生命线**：昵称/签名/聊天/动态/评论/媒体三道审核（前端提示 + 后端同步/异步检测 + IM 回调），陪玩类目因色情、导流、私下交易被封小程序风险高。
2. 陪玩**实名认证** + 平台留存认证记录。
3. 必须提供**账号注销入口**与隐私政策/用户协议。
4. 支付资金可追溯：支付/退款/结算全部保留原始报文与流水。
5. 结算冻结期内发生退款的，优先从待结算金额冲抵。
6. 敏感词库与举报处理 SLA 形成运营机制。
