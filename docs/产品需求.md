## 一、项目概述

### 1.1 产品定位

一个基于微信小程序的游戏陪玩点单平台。老板（普通用户）可以浏览、筛选陪玩，通过**指定单、公开派单、客服派单**三种方式下单，使用平台虚拟代币"星星"完成付款与送礼；陪玩接单提供服务并获得可提现收入；平台通过管理后台运营内容、管理人员、处理订单与资金。

### 1.2 功能全景（一期 11 项主要功能）

1. 查看点单须知与陪玩价格
2. 查看活动介绍
3. 系统播报
4. 陪玩列表、排行榜、陪玩详情页
5. 下单系统（指定单 / 公开派单 / 客服派单）
6. 送礼系统
7. 用户个人主页、陪玩个人主页
8. 用户充值
9. 陪玩提现
10. 联系客服
11. 用户注册与账号注销

### 1.3 角色定义

| 角色 | 说明 |
|---|---|
| 游客 | 未登录访客，可浏览陪玩列表、详情等无需身份的公开信息 |
| 老板（普通用户） | 注册用户，可充值、下单、送礼 |
| 陪玩 | 在老板账号之上叠加的**附加身份**，可接单赚钱；陪玩账号本身也具备老板能力，但一期关闭其老板侧入口（见 1.5） |
| 管理员 | 管理后台最高权限角色 |
| 客服 | 管理后台中权限级别低于管理员的角色，**不建模为普通用户**；负责代发派单链接、核实申诉并操作强制退款；API 级权限由后端代码按角色分级指定 |
| 系统定时任务 | 承担榜单跑批、超期自动确认、超期自动评价等自动化动作 |

### 1.4 术语约定

| 术语 | 含义 |
|---|---|
| 星星 | 平台唯一虚拟代币，小程序内一切消费均以星星支付，整数计量，**不过期**；人民币仅出现在充值、提现环节 |
| 亲密度 | 衡量某一对"老板 + 陪玩"互动深度的数值（旧称"羁绊值"，已弃用） |
| 数量 | 计费单位，单位为**小时**或**局**（口语中的"下一单"统一改称"数量"，避免与"订单"混淆） |
| 系统 ID | 用户数字 ID，从 **10000** 起递增 |
| 应单 | 仅发生在**选人阶段**：陪玩表达接单意愿，确保老板付款后能顺利开始服务；不等于付款后的"开始服务" |
| Tag | 陪玩的营业板块 / 级别认证标签 |
| 派单窗口 | 公开派单发布后等待陪玩应单的时间窗，默认 120 秒，后台可配 |

### 1.5 一期范围边界

**一期不做**（不建表、不留空心字段）：

- 装扮商城
- 消费积分
- 访客与足迹
- 邀请好友奖励
- 关注 / 粉丝
- 专属礼物、礼物等级区分

**一期特殊限制**：陪玩角色在小程序端**隐藏充值入口与充值余额、拦截点单等老板专属行为**；钱包数据结构已先行支持双账户，后续开放无需改表。

### 1.6 外部服务依赖

| 服务 | 用途 | 备注 |
|---|---|---|
| 微信小程序虚拟支付（米大师） | 虚拟代币充值的唯一通道，iOS 侧必须走该通道 | **上线阻断项**，需最早推进并核实小程序服务类目可开通虚拟支付 |
| 腾讯云 IM | 实时通信、在线会话 | 不建本地消息表 |
| 腾讯云短信 | 短信验证码登录 | 不建本地短信通道表 |

## 二、账号体系

### 2.1 登录与注册

- 支持两种登录方式：**微信快捷登录**、**短信验证码登录**（短信服务采用腾讯云短信）。
- 允许游客不登录浏览公开信息。
- **同手机号自动合并账号**：两种登录方式命中同一手机号时，按手机号更新补齐账号字段，合为同一账号，不新建账号；手机号是账号合并主键。
- 用户系统 ID 为数字，从 10000 起递增。

### 2.2 陪玩身份

- 陪玩是普通用户之上的附加身份，而非独立账号体系。
- 陪玩的入驻、考核、升级、Tag 登记均在管理后台操作完成。
- 一期陪玩端关闭老板类入口（见 1.5），后续视产品规划开放。

### 2.3 账号注销

注销的本质是 **个人信息匿名化 ＋ 置注销标记 ＋ 禁止登录**，不做物理删除。

- 订单、评价、礼物、财务凭证等业务与财务数据依法留存（网络日志 ≥ 6 个月、交易凭证 ≥ 5 年）。
- **注销前置条件**：
  1. 名下无进行中订单（有进行中订单的，须等订单结束后才可注销）；
  2. 陪玩的收入余额须先全部提现；
  3. 老板的充值余额不可提现、不可转账，**注销时余额直接作废**（该规则须写入用户协议，作废动作留痕）。

### 2.4 隐私设置

- **隐私号（搜索可见性全局开关）**：老板可自主设置，设为隐私号后不被搜索到；陪玩不允许设隐私号，必须始终可被搜索。
- **榜单隐私**：见 4.2 节。
- **个人主页字段可见性**：一期不做前端字段级配置，字段是否对外返回的规则固化在后端代码中，由后端决定。

## 三、首页与公共内容

### 3.1 营业板块、点单须知与价格表

- 每个营业板块拥有独立的点单须知与价格表；平台另设**总点单须知，效力高于各板块须知**。
- 首页展示不同营业板块的卡片；点击卡片进入板块详情页，可查看：总点单须知、板块专属点单须知、该板块价格表、全局加价项目录，以及该板块下的认证陪玩列表（默认随机排序、下拉分页加载，D-005）。
- 后台可编辑总须知、各板块须知与价格表。
- 须知为**带版本号的长文本**：下单付款前强制弹出，先展示总须知、再展示板块须知；老板须滑至最底部点击"我已悉知"才可继续支付，知悉动作按须知版本**留痕、不可篡改**。

### 3.2 活动介绍

- 首页展示活动 banner，多个活动依次滚动播放；点击 banner 进入活动详情页，查看活动详细介绍与参与方式。
- 活动分**进行中 / 已结束**状态，过期活动自动下架。
- 后台修改活动后前台实时生效。
- 活动详情页一期 C 端**纯展示、不设"参与"按钮**（D-005）：用户完成活动规则中的指定操作后，由后台自动判定是否参与成功，C 端不承载参与交互；判定所需的参与记录由后端另行建模，不阻塞 C 端上线。

### 3.3 系统播报

- **位置**：首页顶部播报展示区，滚动播报最新动态，营造活跃氛围。
- **内容范围**：**仅保留送礼播报，充值播报已取消**。播报由系统在送礼行为发生后自动生成，无需人工发布。
- 星星是虚拟代币，播报中的金额**无需脱敏**。
- 后台可配置：播报开关、展示条数、播报频率。
- 前端轮询拉取播报，不做服务端推送。

### 3.4 搜索

- **入口**：首页顶部搜索框、陪玩列表页顶部搜索框。
- **规则**：
  - 支持按**昵称模糊匹配**或**系统 ID** 搜索；重名用户不做特殊区分，靠头像与 ID 辨别；
  - 点击搜索结果跳转对应主页：陪玩进入陪玩详情页，老板进入用户个人主页；
  - 老板设为隐私号后搜不到，取消后恢复可搜；陪玩始终可被搜索。
- **验收要点**：两处搜索框均可按昵称 / 系统 ID 搜到并正确跳转；隐私号开关生效；陪玩不可隐藏。

## 四、陪玩发现：列表、排行榜与详情页

### 4.1 陪玩列表

**目标**：用户能浏览全店陪玩，并通过推荐排序与条件筛选快速找到想下单的人。

**入口**：底部导航栏第 2 个分区「陪玩」。底部导航共 4 个 Tab，依次为：**首页 / 陪玩 / 会话 / 我的**（D-004）。

**卡片信息**：头像、昵称、性别、年龄、所属营业板块、陪玩等级、个人简介、在线状态，并支持语音试听。

**推荐排序（默认排序机制）**：

- 进入列表时默认**随机**推荐；
- 可手动切换三种排序：
  1. 优质陪玩推荐——按优质程度排序；
  2. 热门陪玩推荐——按热门程度 / 接单情况排序；
  3. 新人陪玩推荐——按进店时间先后排序；
- 排序依据由后台根据陪玩进店情况、接单情况、评价情况自动计算。

**条件筛选**：

- 五个筛选维度：营业板块、性别、陪玩级别、在线状态、音色；
- 各维度可单独使用，也可组合使用，列表实时刷新；
- 筛选与推荐排序可叠加：先按筛选条件过滤，再按当前排序规则展示。

**验收要点**：默认随机；三种排序切换结果与后台规则一致；五个维度单独及组合均生效；筛选与排序同时作用正确。

### 4.2 排行榜

**目标**：展示陪玩接单流水、老板消费、老板与陪玩亲密度的排名，激励消费与互动。

**入口**：

- 首页顶部：搜索框旁的排行榜入口（首页不再设通知入口，通知统一在「会话」Tab 的系统消息会话展示，D-001）；
- 陪玩列表页顶部：展示头牌陪玩榜前三名大头像（第 1/2/3 名），旁附「点击查看完整榜单」，点击进入完整排行榜。

**榜单周期**：

- 支持日榜（00:00–24:00）、周榜（周一 00:00 至周日 24:00）、月榜（当月 1 日至最后一日），按中国时区计算，可切换；数据结构预留小时榜扩展。
- 榜单由定时任务跑批生成，**跑批频率与榜单周期同名**（例如日榜每日零点更新，周榜、月榜以此类推）；**不做推送，由小程序端自行拉取**。
- 每个榜单只显示**前 10 名**；分数并列时不区分先后。

**三类榜单**：

| 榜单 | 排名依据 | 排名单位 |
|---|---|---|
| 头牌陪玩排行榜 | 陪玩接单流水 | 陪玩 |
| 老板消费排行榜 | 老板消费金额 | 老板 |
| 亲密度排行榜 | 老板与陪玩的亲密度（随老板对该陪玩的消费提升） | 一对"老板 + 陪玩"关系 |

- 每个榜单展示：排名、头像、昵称，以及对应的流水 / 消费金额 / 亲密度值。
- **上榜口径**：完成订单才上榜；发生退款时扣减相应数值。
- **跳转**：点击榜单中的陪玩卡片，跳转该陪玩详情页。

**榜单隐私设置（用户自主选择）**：

- 流水 / 消费金额：公开或隐藏；
- 头像、昵称：匿名或公开；隐私号用户**仍占榜单名额**，匿名时显示配置文案（默认"老板"，文案后台可配）；
- 亲密度值：匿名或公开；
- 设置隐藏 / 匿名后，榜单对应信息以隐藏 / 匿名形式展示。

**验收要点**：两个入口均可进入榜单；日 / 周 / 月区间正确；三类榜单各显示前 10 名且排序正确；亲密度榜以"老板 + 陪玩"一对为单位；点击陪玩可进详情页；各项隐私设置生效。

### 4.3 陪玩详情页

**目标**：让用户全面了解陪玩，并可试听、送礼、打赏、下单。

**入口**：陪玩列表卡片、排行榜卡片等点击进入。

**展示内容**：

- 头像、背景图、昵称、性别；
- 个人介绍 / 个性签名；
- 亲密关系（恋爱）状态：平台要求陪玩公示恋爱状态，恋人绑定规则见 4.4；
- 在线状态；
- 所属营业板块、陪玩级别（以 Tag 展示）；
- 语音试听。

**板块与级别 Tag 机制**：

- Tag 由平台在陪玩完成考核培训、入职认证后，通过系统后台登记生成并自动展示，**陪玩不可自行编辑**；
- 平台可随时取消 Tag；Tag 被取消后，陪玩**不能再接对应板块 / 级别的订单**（硬性拦截）；
- Tag 操作时若陪玩存在进行中订单则拦截；若异常漏过，进行中的订单继续完成。

**主页资料编辑与审核**：

- 主页展示内容陪玩可自行编辑；
- 其中**头像、背景图、昵称、个人介绍**四项的修改须经平台后台审核，审核通过后才对外展示；
- 审核目的是拦截不良图片与违规违法内容；审核驳回的修改不生效，保持原内容。

**礼物墙**：规则见 6.2。

**订单评价**：

- 详情页展示该陪玩收到的全部订单评价；
- 订单结束后系统弹出评价，老板可打分并填写文字评价；
- 老板不手动打分时默认 5 星满分；超过配置期限仍未评价的，系统自动给予 5 星（期限后台可配）；
- 老板可选择匿名评价或公开评价，按选择展示。

**操作按钮**：

- **下单按钮**：跳转下单详情页；
- **打赏按钮**：即给该陪玩送礼物（流程见 6.1）；
- **举报入口**（D-005）：位于详情页「更多」菜单，点击后拉起客服 IM 会话承接举报内容；一期不建独立举报工单与数据表，客服侧处理流程走后台。

**验收要点**：信息展示齐全；Tag 后台登记、不可自改、取消后硬拦截接单；四类资料修改需审核；评价含默认 5 星与匿名 / 公开选择；下单与打赏按钮跳转正确。

### 4.4 恋人（亲密）关系

- 老板发起绑定请求，陪玩确认后生效；**双方均可主动解除，无冷静期**。
- 绑定关系展示在陪玩主页；可选择**匿名展示**：主页只显示"恋爱中"，不显示对方身份。
- 关系变更时若陪玩有进行中订单则拦截；异常漏过的，进行中订单继续完成。

## 五、下单系统

### 5.1 总体流程与订单模型

**标准主流程**：

> 用户选人（可多人）→ 选择并填写需求、付款 → 陪玩开始 → 陪玩结束 → 老板确认

要点：

- "应单"只发生在公开派单 / 客服派单的**选人阶段**，付款后不再有"接单"动作，陪玩收到的是"开始服务"通知。
- **多陪玩订单的数据形态**：支付成功后，按陪玩人数生成 **N 条相互独立的订单**，共享同一支付批次号，仅在 UI 层合并展示方便老板操作；各订单可独立开始、结束、评价、退款。
- **支付规则**：小程序内一律以星星支付，扣减老板的充值余额；多陪玩合并支付时若余额不足，**整单失败、不生成任何订单**，引导充值后重新支付，不做部分下单。
- 支付成功后订单状态为「待开始」，同时更新排行榜相关数值。

### 5.2 计价规则

- **单价维度**：`板块 × 陪玩等级 × 模式` 共同确定单价；计价方式分**按小时（星星/小时）**与**按局（星星/局）**两种，具体数值由管理员后台维护。
- **模式字典按板块单独配置**（例：无畏契约板块下有匹配 / 娱乐模式 / 趣味单 / 排位，排位再细分黄金及以下、铂金、钻石、超凡、神话一/二/三、赋能等）。
- **加价项目录为全局配置**：每个加价项是固定星星金额，多个加价项**可叠加、简单相加**（例：亚服 / 欧美服 / 甜蜜单 / 特殊单 / 单口 / 一陪二 / 一陪三 / 一陪四）。
  - "一陪二 / 一陪三 / 一陪四"含义为一个陪玩陪多个老板，**仅作标签处理，系统不核查实际人数**；选择时可填数量。
- **数量 ≥ 1**，老板可加单。例：单价 40 星星/小时，数量 3，则该陪玩订单金额为 3 × 40 = 120 星星。
- **总价公式**：`总价 = Σ（各陪玩单价 × 数量）＋ 加价项固定金额合计`。
- 下单时对单价、加价项做**快照**，后台后续改价不影响历史订单。
- 下单可填写**时间段**，表示老板预约的服务时段，不一定立即开始（预约规则见 5.8）。

### 5.3 方式一：老板指定单

**目标**：老板选择特定陪玩（可多个），填写时长、时间段、板块后支付并开始陪玩。

**入口**：

- 陪玩主页下单按钮（交互类似"加入购物车"）；
- 筛选结果中的下单按钮。

**规则**：

1. 已选陪玩展示头像与简短自我介绍；
2. 板块修改规则（D-002）：仅选 **1 名陪玩**时可重新选择板块，候选项限该陪玩**已认证**的板块（例：从英雄联盟板块筛选出的陪玩，可改到其已认证的无畏契约）；选择 **2 名及以上陪玩**时板块锁定、不可修改，选择器置灰并提示；
3. 陪玩类型在指定单模式下变灰、仅展示：性别（男 / 女 / 不限）、等级（娱乐 / 技术 / 优技 / 顶技 / PRO / 不限）；
4. 选择模式（取所选板块的模式字典）；
5. 选择加价项（"一陪多"类在此选择数量）；
6. 可填写备注；
7. 点击下单后、付款前强制弹出点单须知，滑至最底部点击"我已悉知"才可继续（知悉留痕）；
8. 以星星余额完成支付（余额不足按 5.1 整单失败处理）。

### 5.4 方式二：公开派单

**目标**：老板先发布陪玩需求，陪玩主动应单，老板在有意愿的陪玩中选人确认后下单。

**入口**：「陪玩」Tab（陪玩列表页）右侧悬浮按钮，可上下拖动（D-004）；游客点击引导登录，陪玩身份下按钮隐藏。

**流程与规则**：

1. 老板在派单界面填写游戏板块、陪玩类型、模式；界面随填写内容**实时更新预估价格**；
2. 发布后界面进入等待状态，等待窗口默认 **120 秒**（后台可配）；期间符合条件的陪玩在「会话」Tab 收到 **IM 派单消息提醒**（D-003，完全替代原弹窗方案，消息留痕可回看，后台/离线错过后进入小程序仍可查看），可选择接受或拒绝，接受即进入老板的待选列表；
3. 老板界面实时展示有应单意愿的陪玩列表，可添加一个或多个进入下单列表；
4. 挑选完成后点击下单，进入结算页：回填已填好的板块、类型、模式、陪玩列表与总价格；
5. 付款前强制知悉点单须知（留痕），随后星星支付。

**异常处理**：

- 窗口超时后派单失效，老板可重新发起；
- 应单但未被选中的陪玩，应单记录**自动失效，不推送任何提醒**。

### 5.5 方式三：客服派单

**目标**：老板通过对话向客服提出需求，由客服代发派单，生成链接后老板自行选人下单。

- 客服是管理后台角色（权限低于管理员），代发派单链接走管理后台权限体系；
- 派单链接的有效期与公开派单窗口取同一配置（默认 120 秒）；
- 老板打开链接后的选人、结算、知悉须知、支付流程与公开派单完全一致。

### 5.6 订单状态机与异常处理

订单共六个状态：**待开始 → 服务中 → 待确认 → 已完成 → 已评价**，以及异常终态**已退款**。

| 状态 | 含义 | 进入条件 |
|---|---|---|
| 待开始 | 已付款，等待陪玩开始服务 | 支付成功，按陪玩人数生成订单 |
| 服务中 | 陪玩已点击开始 | 陪玩点「开始」（预约单允许提前开始） |
| 待确认 | 陪玩已点击结束，等待老板确认 | 陪玩点「结束」 |
| 已完成 | 服务完成确认 | 老板确认，或超期由系统自动确认 |
| 已评价 | 评价完成 | 老板评价，或超期系统自动 5 星 |
| 已退款 | 退款终态 | 见下方四类退款场景 |

**待开始阶段的异常分支**：

1. **老板主动取消**：付款后、陪玩开始前，老板可随时取消，星星原路退回充值余额；
2. **陪玩拒绝服务**：陪玩点击拒绝，全额退星星；
3. **超时未开始**：超过配置的等待时长陪玩仍未开始，老板可二选一：
   - 继续等待（重新计时一个相同时长）；
   - 放弃等待，退款星星；
4. **客服强制退款**：服务进行中陪玩失联或中途停止，老板将订单号发给客服，客服核实属实后在后台操作强制退款，**操作人与原因必须留痕**。

**待确认阶段的异常分支**：

- 陪玩点结束后老板超期不确认的，超过配置天数由**系统自动确认**，订单进入已完成。

**退款通用规则**：

- 退款共四种类型：老板取消、陪玩拒绝、超时退款、客服强制退款；
- 所有退款均原路退回老板充值余额，并**连带扣减相应亲密度（下限为 0，不允许负值）**与榜单数值；
- 订单全部状态流转写订单事件日志（操作人角色、前后状态、备注），作为审计与申诉依据。

完整状态流转图见附录 A。

### 5.7 订单评价

- 订单完成后系统弹出评价，老板可打 1–5 星并填写文字评价；
- 老板不手动打分则默认 5 星；超过配置期限未评价，系统自动给予 5 星并标记为系统默认评价；
- 支持匿名 / 公开评价，按老板选择在陪玩详情页展示。

### 5.8 预约时段规则

- 预约单**允许陪玩提前开始**服务；
- 预约时段**不占用陪玩档期**，不拦截其他老板对该陪玩下单；
- 具体服务时间由老板与陪玩在腾讯云 IM 会话中私下协商。

## 六、礼物与亲密度

### 6.1 送礼

**入口**：陪玩详情页的「送礼 / 打赏」按钮。

**规则**：

1. 点击后弹出礼物列表；一期**不做专属礼物、不区分礼物等级**；
2. 一次送礼只能选择**一种**礼物，但同一种礼物**数量可多个**；
3. 统一使用星星余额（充值余额户）支付，余额不足时引导充值；
4. 送礼成功后：
   - 触发全频道系统播报（送礼是唯一播报来源，规则见 3.3）；
   - 更新该陪玩的礼物墙；
   - 增加老板与该陪玩的亲密度；
5. 老板在个人主页可查看自己的送礼记录，并可设置是否对外公开；
6. 发生退款时，连带扣减亲密度（下限 0）。

### 6.2 礼物墙

- 位于陪玩详情页，展示该陪玩收到的全部礼物；
- 按**礼物个数**统计两个数据：累计收到数量、去重后的送礼人数（即"有多少人送过"）；
- 已收到的礼物点亮展示并显示数量；未收到的礼物灰色展示；
- **不展示送礼人身份**。

### 6.3 亲密度

- 计量对象是一对"老板 + 陪玩"关系，而非用户单方；
- 计算依据：**已正常结束的订单金额 ＋ 礼物金额**，按后台配置的换算比例折算；
- 发生退款时连带扣减，**下限为 0，不允许负值**；
- 每次变动保留流水；
- 应用场景：亲密度排行榜、个人主页亲密关系展示。

## 七、钱包、充值与提现

### 7.1 代币与钱包账户结构

- 小程序内一切金额单位均为星星（整数），人民币金额仅出现在充值单与提现单中；星星不过期。
- 每个用户的钱包分两个账户记账：

| 账户 | 资金来源 | 用途与规则 |
|---|---|---|
| 充值余额 | 人民币充值入账 | 老板下单、送礼均从此支出；**不可提现、不可老板间转账**，只能通过下单、送礼消耗；注销时余额作废 |
| 收入余额 | 陪玩接单、收礼（扣佣后）入账 | 仅陪玩使用，**可提现** |

- 每笔余额变动写钱包流水（账户类型、收支方向、变动数、变动前后余额、业务来源单据），并通过乐观锁防止并发记账超支。
- 一期陪玩端隐藏充值入口与充值余额、拦截老板类行为；双账户结构先行落地，后续开放无需改表。

### 7.2 充值

- 一期唯一充值通道：**微信小程序虚拟支付（米大师）**，iOS 侧虚拟代币充值必须走该通道；
- 汇率后台可配，初始规则：
  - iOS 平台：1 人民币 = 7 星星；
  - 其他平台：1 人民币 = 10 星星；
- 充值单记录人民币金额、成交时汇率快照、到账星星数与支付通道订单号；
- 该通道能否开通取决于小程序服务类目资质，是**上线阻断项，须最早推进**。

### 7.3 平台抽佣

- **订单抽佣与礼物抽佣是两个独立配置项**（算法一致、比例可分别调整），示例比例均为 15%；
- 示例：老板支付 100 星星，按 15% 抽佣后，陪玩收入余额实际到账 85 星星；
- 每笔抽佣留存抽佣明细：抽佣前总额、抽佣比例、平台抽成、陪玩净得。

### 7.4 退款资金规则

- 所有退款的星星**原路退回老板充值余额**，不进入收入余额；
- 退款触发场景与审批规则见 5.6；其中客服强制退款必须记录操作人与原因；
- 退款同步扣减亲密度（下限 0）及榜单相关数值。

### 7.5 陪玩提现

- 仅陪玩的**收入余额**可申请提现；提现汇率后台可配，初始规则：1 星星 = 0.1 人民币；
- **起提门槛可配置**，低于门槛不可发起；
- 到账方式由陪玩自选，**微信零钱与银行卡均需支持**；收款账户信息加密快照存储；
- 每笔提现**必须经后台审核**；审核驳回后星星回冲收入余额并写流水；
- 一期**不做人工转账回填凭证**功能；
- 陪玩注销账号前须先提现全部收入余额。
