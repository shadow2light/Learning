# 后端表结构

> **版本**：2026-11-23 全文重写，依据《需求澄清记录.md》第一、二轮澄清结论。
> **权威性**：本表结构为 L3 设计文档，与《产品需求.md》《需求澄清记录.md》冲突时以后两者为准。
>
> **通用约定**：
> - 所有业务表继承 `BaseTable` 公共字段；所有系统 ID 为数字，从 **10000** 起递增。
> - 小程序内一切金额单位均为虚拟代币**星星**（整数存储）；人民币金额仅出现在充值单、提现单中。
> - 一期**不做**（澄清 P0-6）：装扮商城、消费积分、访客与足迹、邀请好友奖励、关注/粉丝——不建表、不留空心字段。
> - 实时通信走**腾讯云 IM**、短信验证码走**腾讯云短信**、iOS 等虚拟代币充值走**微信虚拟支付（米大师）**，均不建本地消息/通道表。

```
struct BaseTable {
    id        int;      // 系统 ID，10000 起递增
    createdAt DateTime;
    updatedAt DateTime;
    enabled   bool;     // 逻辑启停，业务数据不物理删除
    authorId  int;      // 创建/更新者 userId，系统任务填 0
}
```

配置键清单（后台可改，代码禁止硬编码）：

| configKey | 含义 | 默认/示例 |

| `broadcast.gift.frequency` | 送礼播报频率 | 待定 |
| `broadcast.gift.display_limit` | 送礼播报展示条数 | 待定 |
| `order.auto_review.days` | 超期未评价自动 5 星期限 | 待定 |
| `order.auto_confirm.days` | 老板结束确认超期自动确认天数（P0-5） | 待定 |
| `withdraw.min_star` | 提现起提门槛（P1-9） | 待定 |

## 三、用户与陪玩

### 1. 用户表 User（老板与陪玩共享，陪玩是附加身份）

```
struct User : BaseTable {
    nickname          string;
```

## 五、订单与评价

### 1. 订单状态枚举（按澄清第三节状态机重画）

```
enum OrderState {
    PENDING_START,   // 待开始：已付款，等待陪玩开始
    IN_SERVICE,      // 服务中：陪玩已点开始
    PENDING_CONFIRM, // 待确认：陪玩已点结束，等待老板确认
    COMPLETED,       // 已完成：老板确认或系统超期自动确认
    REVIEWED,        // 已评价：老板评价或超期自动 5 星
    REFUNDED         // 已退款（全额/客服强制退款）
}

enum RefundType {   // 仅 state=REFUNDED 时有值
    BOSS_CANCEL,     // 老板开始前主动取消，原路退款
    PLAYMATE_REFUSE, // 陪玩拒绝服务，全额退款
    TIMEOUT,         // 超时未开始，老板选择退款
    CS_FORCE         // 服务中失联/中止，客服核实后强制退款
}

enum OrderSource {
    DIRECT,          // 指定单
    DISPATCH,        // 公开派单
    CS_DISPATCH      // 客服派单
}
```

### 2. 订单表 Order（多陪玩订单：每个陪玩一条独立订单，同批次共享 orderGroupNo，UI 合并展示）

```
struct Order : BaseTable {
    orderNo            string;
    orderGroupNo       string;     // 同一笔合并支付的批次号，N 条订单共享
    bossUserId         int;
    playmateId         int;
    source             OrderSource;
    dispatchId         int;        // 派单来源时关联，指定单为 0
    plateId            int;
    plateModeId        int;
    playmateLevelId    int;
    priceType          int;        // 0 按小时 1 按局
    unitStarPrice      int;        // 单价快照（星星）
    quantity           int;        // 数量（小时数/局数，≥1）
    additionalStarFee  int;        // 加价项合计（固定金额相加，可叠加）
    totalStarPrice     int;        // 应付星星 = 单价×数量 + 加价合计
    appointmentStartAt DateTime;   // 预约开始时段（允许提前开始，不占档期，P1-2）
    appointmentEndAt   DateTime;
    remark             string;     // 老板备注
    state              OrderState;
    refundType         RefundType;
    // 关键时间点与超时计时
    paidAt             DateTime;
    startDeadlineAt    DateTime;   // paidAt + 等待时长配置；继续等待则重置
    startedAt          DateTime;
    endRequestedAt     DateTime;   // 陪玩点结束
    confirmDeadlineAt  DateTime;   // endRequestedAt + 自动确认天数配置
    confirmedAt        DateTime;
    completedAt        DateTime;
    refundedAt         DateTime;
}
```

支付规则（P1-5）：合并支付时星星余额不足 → 整单失败、不生成任何订单，引导充值后重付。

### 3. 订单事件流水表 OrderEvent（全部状态流转留痕，客服强制退款审计依据）
