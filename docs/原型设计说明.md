## 一、设计范围与角色

| 角色 | 原型覆盖 | 说明 |
|---|---|---|
| 游客 | ✅ | 可浏览公开页，触发交易/社交动作时引导登录 |
| 老板 | ✅（主线） | 充值、下单、派单、送礼、评价、个人主页 |
| 陪玩 | ✅ | 接单、订单操作、提现、资料维护；一期隐藏充值与点单入口（PRD 1.5） |
| 客服 | ⚠️ 仅 C 端会话入口 | 客服工作台属管理后台，本版仅列框架 |
| 管理员 | ❌ | 管理后台，见第七章清单 |

**终端形态**：微信小程序（竖屏移动端）；iOS 与其他平台在充值页存在汇率差异（PRD 7.2）。

## 五、页面线框说明（小程序 C 端）

### P01 登录页

- **对应需求**：PRD 2.1、2.4
- **页面目标**：完成微信快捷登录或短信验证码登录；游客可跳过。
- **入口**：启动小程序；游客触发受限操作时的登录引导（M08）。
- **线框区块（自上而下）**：
  1. 品牌区：Logo、Slogan【待补充】；
  2. 微信快捷登录按钮（主按钮）；
  3. 短信验证码登录入口 → 展开手机号输入 + 验证码输入 +「获取验证码」（倒计时 60s【待补充确认】）；
  4. 用户协议/隐私政策勾选（未勾选不可登录，协议文本【待补充】）；
  5. 「随便看看」游客模式入口。
- **交互与跳转**：
  - 同手机号两种登录自动合并账号，用户无感知（PRD 2.1）；
  - 登录成功回到来源页。
- **状态异常**：验证码错误/过期、网络异常、用户拒绝微信授权。
- **待补充**：视觉风格、协议文本、验证码倒计时秒数、启动页是否独立。

### P02 首页

- **对应需求**：PRD 3.1、3.2、3.3、4.2
- **页面目标**：内容分发与功能集散。
- **入口**：底部 Tab（序号待补充）。
- **线框区块（自上而下）**：
  1. 顶部栏：搜索框（点击进 P06）、通知图标【通知内容待补充】、排行榜入口图标；
  2. 系统播报滚动区：仅送礼播报文案轮播，金额不脱敏；
  3. 活动 Banner 区：多活动自动轮播，点击进 P04；
  4. 营业板块卡片区：每卡片含板块名、图标，点击进 P03；
  5. 【待补充：是否放推荐陪玩/头牌等其他区块】。
- **交互与跳转**：见各子页面。
- **状态异常**：无活动/无板块时的空态。
- **待补充**：播报滚动样式（横滚/竖滚）、卡片排布列数、通知中心内容定义。

### P03 板块详情页（须知 + 价格表）

- **对应需求**：PRD 3.1、5.2
- **页面目标**：展示总须知、板块专属须知与价格表。
- **入口**：首页板块卡片。
- **线框区块**：
  1. 板块标题区；
  2. Tab 或分段：总点单须知 / 板块点单须知 / 价格表；
  3. 须知正文（长文本，来自带版本的后台配置）；
  4. 价格表：按「等级 × 模式」展示单价（星星/小时、星星/局两种计价类型）；
  5. 【待补充：是否在此页放「去下单/找陪玩」按钮】。
- **交互与跳转**：须知仅浏览；正式知悉留痕发生在下单前 M01。
- **待补充**：价格表是表格还是卡片、加价项目录是否在此展示。

### P04 活动详情页

- **对应需求**：PRD 3.2
- **线框区块**：
  1. 活动 Banner 大图；
  2. 活动标题、起止时间、状态标识（进行中/已结束）；
  3. 富文本正文：详细介绍与参与方式；
  4. 参与按钮（过期活动按钮置灰或隐藏）【待补充：参与动作是什么——跳板块/跳下单/纯展示】。
- **状态异常**：过期活动自动下架，不可进入；历史活动是否有列表页【待补充】。

### P05 陪玩列表页

- **对应需求**：PRD 4.1
- **页面目标**：浏览、排序、筛选全店陪玩。
- **入口**：底部 Tab 第 2 个。
- **线框区块（自上而下）**：
  1. 顶部搜索框（进 P06）；
  2. 头牌榜前三头像区（1/2/3 名大头像 +「点击查看完整榜单」→ P07）；
  3. 排序栏：默认「随机」，可切换优质/热门/新人（单选分段控件或下拉）；
  4. 筛选入口按钮 → 筛选抽屉：板块、性别、级别、在线状态、音色五维度，可多选/组合，带「重置/确定」；
  5. 陪玩卡片列表（分页加载、下拉刷新），卡片字段：头像、昵称、性别、年龄、板块、等级、简介、在线状态、语音试听按钮；
  6. 卡片操作：点击卡片 → P08；卡片上是否有快捷下单按钮【待补充】。
- **交互规则**：先筛选过滤再按排序展示；默认随机；筛选条件回填与已选标签展示。
- **状态异常**：筛选无结果空态；离线陪玩是否置灰【待补充】。
- **待补充**：列表单列/双列、语音试听时长与播放形态。

### P06 搜索页 / 搜索结果页

- **对应需求**：PRD 3.4
- **入口**：首页、陪玩列表顶部搜索框。
- **线框区块**：
  1. 搜索输入框（支持昵称模糊、系统 ID 精确）+ 取消；
  2. 未输入态：【待补充：搜索历史/热门搜索是否做】；
  3. 结果态：用户结果列表，区分陪玩/老板标识；点击分别跳 P08 / P17；
  4. 无结果态：提示文案（靠头像与 ID 辨别重名）。
- **规则**：老板隐私号不出现在结果中；陪玩始终可搜。
- **待补充**：是否分 Tab（全部/陪玩/老板）、结果卡片字段。

### P07 排行榜页

- **对应需求**：PRD 4.2
- **入口**：首页排行榜图标；陪玩列表顶部「查看完整榜单」。
- **线框区块**：
  1. 周期切换：日榜/周榜/月榜（数据结构预留小时榜，UI 是否暴露【待补充】）；
  2. 榜单类型 Tab：头牌陪玩榜 / 老板消费榜 / 亲密度榜；
  3. 前三领奖台样式（大头像、名次、昵称、数值）；
  4. 第 4–10 名列表条目：排名、头像、昵称、流水/消费/亲密度值；
  5. 隐私态展示：金额隐藏显示「-」；匿名显示配置文案（默认"老板"）；亲密度匿名同理；
  6. 榜单隐私设置入口（跳转 P19 或本页浮层）。
- **交互**：点陪玩条目 → P08；老板条目 → P17（受隐私号限制）；数据前端定时拉取，不做推送。
- **状态异常**：榜单未生成/数据为空。
- **待补充**：并列名次的视觉处理、领奖台设计风格。

### P08 陪玩详情页

- **对应需求**：PRD 4.3、4.4、5.3、6.1、6.2
- **页面目标**：全面了解陪玩并发起试听、下单、打赏。
- **入口**：陪玩卡片、排行榜、搜索结果、订单/IM 头像。
- **线框区块（自上而下）**：
  1. 顶部背景图 + 返回/更多【更多操作待补充】；
  2. 头像、昵称、性别、年龄、在线状态；
  3. Tag 区：板块 Tag、等级 Tag（后台登记，不可自改；取消后硬拦截接单）；
  4. 个性签名/个人介绍；
  5. 恋爱状态条：单身/恋爱中；匿名绑定时仅显示「恋爱中」；
  6. 语音试听条（播放/暂停、时长）；
  7. 礼物墙：全部礼物图标网格，已收到点亮并显示数量与送礼人数，未收到灰色；不展示送礼人；
  8. 评价区：评分汇总【待补充：是否做评分均分】+ 评价条目（星级、文字、匿名/公开昵称、时间），分页；
  9. 底部固定操作栏：「下单」（→ P09）、「打赏」（→ M02）。
- **待补充**：区块是否可由陪玩拖拽排序、举报入口是否放在「更多」。

## 六、核心流程的页面串联

> 业务状态机以 PRD 附录 A 为准，本节只标注每一步落在哪张原型页面/弹窗，供 Figma 连线（Prototype Flow）使用。

### 流程 F1：指定单下单（含多陪玩）

```
P05/P08 选陪玩（可多人，类似加购物车）
  → P09 填需求（板块/模式/加价/数量/预约/备注）
  → M01 须知弹窗（滑到底 → 我已悉知，留痕）
  → P11 结算支付（星星余额）
       ├─ 余额不足 → 整单失败引导 → P21 充值 → 返回 P11 重付
       └─ 支付成功 → 结果页（生成 N 条待开始订单）→ P13 订单详情
            ├─ 开始前：老板 M05 取消 / 陪玩拒绝 / 超时 M06 → 已退款
            └─ 陪玩开始(P27) → 服务中 → 陪玩结束 → 待确认
                 ├─ 老板确认 / 超期自动确认 → 已完成
                 └─ M07/P14 评价（超期自动 5 星）→ 已评价
```

### 流程 F2：公开派单 / 客服派单

```
P10-A 发布需求（预估价实时刷新）
  → P10-B 120s 等待（陪玩端 M04 应单 → 实时进列表）
       ├─ 超时无人应单 → 失效 → 重新发起
       └─ 老板选人（可多个）→ P11（回填信息）→ M01 → 支付 →（同 F1 后半段）

客服派单：P16 客服 IM 会话 → 客服代发链接（同有效期）→ 打开 P10-B →（同上）
未被选中的应单：自动失效，无推送
```

### 流程 F3：送礼

```
P08/P15 入口 → M02 选礼物（一种、数量多个）
  → 余额校验（不足 → P21）→ 赠送成功
  → 播报入队（首页 P02 滚动展示）+ 礼物墙更新 + 亲密度增加
  → 退款场景连带扣减亲密度（下限 0）
```

### 流程 F4：充值与提现

```
充值：P20/P11/P15 → P21 选档位 → 米大师收银台 → 回调入账 → 充值记录
提现：P20 收入余额 → P22 选方式（微信零钱/银行卡）→ 后台审核
        ├─ 通过 → 打款 → 已到账
        └─ 驳回 → 星星回冲 + 原因展示
```

### 流程 F5：注册登录与注销

```
启动 → P01（游客可跳过）→ 微信/短信登录（同手机号自动合并）
注销：P25 → 前置校验（无进行中订单/收入已提现）→ M09 明示余额作废 → 匿名化+禁止登录
```

## 九、Figma 组织建议

1. **文件划分**：`C 端小程序原型`、`管理后台原型` 两个文件，避免单文件过载。
2. **页面命名**：沿用本文档编号，如 `P05 陪玩列表`、`M01 须知弹窗`，便于需求-原型双向追溯。
3. **Frame 尺寸**：以微信小程序主流机型尺寸为基准（如 375×812），组件用 Auto Layout。
4. **组件库先行**：先建第三章 3.3 的通用组件与 3.4 的弹窗，再拼页面；星星金额、订单状态标签做成带变体的 Component。
5. **原型连线**：按第六章 F1–F5 建 Prototype Flow，异常分支（退款、超时、余额不足、空态）单独连一组流程，避免遗漏。
6. **多角色视图**：同一页面用 Variant 或并排 Frame 表达游客/老板/陪玩差异，配合第四章矩阵自查。
7. **AI 生成用法**：可将每个 P 页面的「线框区块」段落直接作为 Figma AI（First Draft 等）的 prompt，生成初稿后按本文档规则校对。
